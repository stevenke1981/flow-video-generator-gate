# Google Flow 影片生成

## 操作

1. 在 Codex Chrome extension 連線的原有 Chrome 工作階段開啟 `https://flow.google.com/`，選擇使用者指定的專案或建立新專案。多帳號依下方「帳號自動輪值」執行，保留既有登入狀態。Flow TV 只供觀賞及尋找範例；其 `Reuse Prompt` 可作為新影片提示詞的起點。
2. 記下影片的主題、動作、場景、鏡頭、畫幅、時長、輸出數、音訊需求、參考素材與儲存位置。**有角色的影片開做前，必須先完成下方「建立 Flow 角色元件」步驟。** 本使用者的 Flow 影片流程須先在專案底部主提示詞框選取 **Agent**；重新整理或重開專案後再次確認。標準流程使用 **Veo 3.1 Lite、直接生成 720p、16:9、8 秒、單支、三項參考素材（Ingredients）**。任務另有指定時依其要求。保留 Flow 生成前確認，核對實際參考素材、模型、時長、畫幅、輸出數、解析度和點數。符合本次生成規格且每支不超過 12 點的影片，依使用者授權直接核准。提案不符時停在確認畫面，勿互動其核准選項。送出前核對 Veo 3.1 Lite、720p 和實際素材均顯示在當次設定或提案。[Google Flow 代理說明](https://support.google.com/flow/answer/17093911?hl=zh-Hant) · [點數計價](https://support.google.com/flow/answer/16526234?hl=zh-Hant)
3. 需要連戲或引用角色元件時用 `Ingredients`；指定起迄畫面時先核對 `Frames` 與角色元件能否同時使用。無角色的純文字影片直接描述可見動作與鏡頭。標準素材配置為三項。有角色時先選本鏡實際入鏡的 Flow 角色元件，再按時間順序加關鍵動作圖；例如單人鏡用一個角色元件與兩張動作圖。無角色且有 B1–B3 時，可依序選入三張。核對介面與模型的素材上限。如果模式或數量限制使必要角色元件無法加入，先改用相容配置或回報缺項，再決定如何生成。跨片段使用聲音設定前，先確認所選模型支援 `Voices`。
4. 使用者要求生成時，每個待辦片段只提交一次，記錄帳號、專案、結果卡或 job 狀態；送出前若點數不足，依輪值規則切換後繼續。結果不明先查原帳號專案，不跨帳號重複生成。每鏡生成後立即從 Flow 下載 720p 原片，驗證畫面、片長、畫幅和音訊後接續下一鏡。發現問題時，先記錄並處理該鏡。
5. 處理既有 360p 原片或任務明確指定 360p 時，先下載驗收，通過後立即逐鏡提升。提升畫質長時間停在「正在提升」且沒有下載結果時，可重新整理同一 Flow 頁面，再核對原帳號、專案、影片、下載成果及是否仍有提升進行中。重新整理後，下載已有的 720p 成品，或在未見作業仍在進行且尚無成品時重試一次。若重試後仍無結果，記錄狀態。避免同時提升多支。主人曾回報重新整理後重試成功，但根本原因未確認。
6. Flow 出現「偵測到異常活動」時，將工作狀態登記為 unusual_activity 並停止自動提交。若主人自行完成同鏡，核對原帳號及專案中可見的結果，再記錄成果。
7. 驗證本機影片存在、可播放，並用 `ffprobe` 或等價工具讀取解析度、長度、影片與音訊串流。只有看到實際影片檔才回報本機交付成功；在頁面顯示「已提交」只代表工作已送出。

## 建立 Flow 角色元件

1. 用當集核准的獨立角色圖，在對應 Flow 專案的「角色」庫為每位入鏡角色建立並儲存角色元件。輸入角色名稱、固定比例、五官、服裝及配件；檢查儲存後的角色卡與來源圖一致。專案已有符合規格的角色元件時，核對後沿用。
2. 在影片提示詞的素材面板選取實際標示為「角色」的元件，或用 Flow 的 `@角色名` 選擇該角色，核對提示詞框顯示角色素材。角色元件鎖定外觀，分鏡圖負責機位、光線、道具和動作。上傳一般圖片、直接輸入角色名字或只有分鏡縮圖，都不能取代角色元件。換帳號或專案後，先核對目標專案可用的角色，缺少時用核准素材建立再提交。[Flow 角色建立](https://support.google.com/flow/answer/16935308) · [影片提示詞加入角色](https://support.google.com/flow/answer/16353334)

## 提示詞防錯（EP01 痛點分析與 EP04 審查）

- 輸入 Flow 提示詞時放慢速度。長提示詞逐段輸入，等上一段穩定顯示再接下一段。送出前從輸入框讀回全文，對照原稿核對句序、時間碼和台詞。
- **說話者綁外觀**：寫「Mimi (the small cream-white bunny with the green mail bag) says (...)」，不要只寫名字；加上「While one character speaks, every other character keeps their mouth closed.」。
- **不寫「together／both say」**，除非兩人各有台詞（EP04 第 03、11、22 鏡原本有此矛盾）。說話那一拍，說話者要在畫面內，不要把台詞放在道具或水面特寫的拍裡。
- **空容器正面寫空**：「The wooden wagon bed is completely empty.」。參考圖不可含本鏡不該有的道具（EP04 舊版 `ep04_05_B1`、`ep04_06_B1` 車上有紅禮盒）。
- **外觀以系列設定為準**（`系列設定/cast.json`）。外部 AI 的分析可能寫錯，例如 Gemini 把米米寫成純白耳朵；米米其實是左耳立起、耳尖淡棕、右耳前折。
- **一拍一個動作**：複雜動作用 still camera；讓角色一開始就在最終位置（例如已坐在船上），不在 8 秒內「推船、爬上、坐穩」。
- Veo 3.1 Lite 原生 720p 實測 190 幀、7.917 秒；台詞時間點會提早或延後（EP04 第 09 鏡提早約 1–2.5 秒），字幕依實際音訊對時。

## 與 Claude 協作

同一集共用 `EPxx_本機製作交接.md` 與 `local_report.md`，動手前先讀，完成後寫回並註明執行者。同一 Flow 專案一次只由一個 agent 提交；他方已送出、終局不明的項目不得重送。修改提示詞時另存新版本（例如 `_v2.json`），不在對方執行中改原檔。

### EP05 起：送件清單與重試上限
- 影片與分鏡由 agent（Claude）用 Claude in Chrome 操作 Flow 送出（Steven 2026-11-19 指定；computer use 對瀏覽器只能看，網頁一律用 Chrome 工具）。照 `pipeline/studio/paste_list.py` 產生的清單一次送一支，等結果、下載、驗收，再寫回 `02_storyboard.json` 後才送下一支。出現「偵測到異常活動」就停，回報 Steven，不換其他自動化方式繞過。
- 同鏡可多人入鏡並依序發言。每句以角色外觀和時間段標出說話者，其他角色以聆聽姿勢反應。
- 把角色、場景、每件道具和指定文字視為獨立元件，逐項正向描述外觀、數量、位置及當拍動作。文字依劇情指定原文、位置與可讀度。
- 同一鏡最多送 3 次（跨帳號、跨專案合計，`flow_tool.py arm` 會強制）；第 3 次仍失敗 → 在交接記 `split_required`，拆成兩鏡（新的 job ID）或改用剪輯救援，不送第 4 次。


## 帳號自動輪值

- 已授權生成時，目前帳號點數若不足以支付下一段影片，依 [固定七帳號順序](references/account-rotation.md) 切到下一個既有帳號。每次切換後核對實際登入帳號、點數、專案、影片設定與角色元件。若原帳號的生成結果不明，先回原專案確認並記錄結果；同一片段最多一筆未確認的提交。
- Pro 排程依每月 1,000 點加每日 50 點計算，兩種點數在各自週期重置，未用完不累積。兩池全滿時以 1,050 點備作餘額規劃。送出前讀取 Flow 當下顯示的餘額、重設時間與成本。[點數說明](https://support.google.com/flow/answer/16526234?hl=zh-Hant)
- 所有帳號都不足時保存剩餘待辦並停止；不自行加值、購買、降低影片規格或為消耗即將到期的點數新增工作。

## 原生語音與音效提示

當使用者需要人物說話、旁白或場景音效，先依目前模型及模式的實際能力，將說話角色、逐字台詞、語言／口音、情緒、說話節奏、說話時機及所需環境音寫入影片提示詞，並留意不要讓台詞長於片段。不要假設每個模型或模式都支援相同的音訊或語音參考功能。

需要跨片段保持聲線時，檢查 Flow 目前是否提供 Voices；Google 文件指出語音參考適用 Omni Flash 的素材（Ingredients）影片模式，可用介面提供的選項及 `@Voice` 指定。以介面、訂閱及實際模型限制為準。語音參考與角色和圖片是否共用配額，以當前介面為準，不自行推測。

生成後檢查實際音軌、台詞內容、語言、音畫同步及跨片段聲線一致性。台詞用 `gpt-transcribe` MCP（OpenAI 線上 API，計費）轉錄核對，步驟見 [本機驗收](workflow.md#4-finish-正式驗收)；不得把音訊檔或 base64 音訊放進模型輸入（模型不支援，會讓整個對話持續報 `Audio input is not available.`）。音訊串流存在不等於已聽懂或通過驗收：沒有實際轉錄或由主人試聽的項目標為 NOT_RUN。若原生語音無法達成需求，可依使用者既有工具、語言和費用授權採用外部旁白，並另行校時字幕。不得把原生語音或外部配音視為已測試，除非有實際證據。

參考：[Google Flow 建立影片及語音參考](https://support.google.com/flow/answer/16353334?hl=en)、[模型與功能](https://support.google.com/flow/answer/16352836?hl=en)。

### 本使用者的語音文字與畫面修正偏好

預設在 Flow 生成英文角色台詞與旁白，中文語音在後製階段另行配音；如使用者對個別任務指定其他語言，依該任務要求。中文配音的語音合成輸入文字預設用簡體中文，這是使用者的發音偏好而非模型保證。保留可重配音的影片與原始音軌，按實際畫面和語音長度校時中文配音及字幕，盡可能維持環境音、音樂與口型同步；若無法分離原聲，應如實說明。字幕仍遵循使用者指定的繁中、簡中及英文版本，分別校對校時。不得假設配音已完成或實際語音已通過驗收。

如成片人物站位、方向或互動有誤，可按使用者指示在支援的 Flow Omni 1.1 影片編輯模式中以原片為基礎修正，寫明要保留的角色、鏡頭及聲音與唯一需要改動的站位；確認 UI 的模型與點數、提交後檢查實際結果。不要把新生成影片視為已通過語音或連續性驗收。
